# Ajustes necessários nos importadores bibliográficos — CSV/TXT, Scopus e Web of Science

## 1. Diagnóstico geral

O problema observado no projeto não parece ser, principalmente, uma coluna inteira sendo importada no lugar de outra. O comportamento mais provável é que o arquivo esteja sendo lido na coluna correta, mas o conteúdo da coluna de afiliações está sendo quebrado de forma simples demais.

Em bases como Scopus e Web of Science, as afiliações normalmente vêm em um único campo textual, misturando:

- nome da instituição;
- departamento, laboratório, centro ou escola;
- rua, número, campus ou endereço;
- cidade;
- estado/província;
- CEP;
- país.

Exemplo típico:

```text
University of Florida, Gainesville, FL 32611 USA
```

Se o importador simplesmente quebra esse texto por vírgula e assume que o último pedaço é o país, ele pode salvar:

```text
FL 32611 USA
```

como se fosse país.

Da mesma forma, se o importador percorre todos os pedaços da afiliação tentando identificar instituições por palavras como `institute`, `center`, `lab`, `school`, `hospital`, etc., ele pode acabar salvando trechos de endereço como se fossem instituições, por exemplo:

```text
30 Xueyuan Rd
1180 Ctr Dr
5510 Nathan Shock Dr
118 Parr St
1280 Montgomery Blvd
```

Esses valores não devem ser cadastrados como instituições. Eles devem ser filtrados no momento da importação ou removidos de documentos já importados.

---

## 2. O que está confirmado no funcionamento atual

No fluxo atual, cada importador preenche um `BibliographicRecordDTO`, que possui campos separados para:

```text
countries
institutions
affiliations
references
authorNames
authorKeywords
indexedKeywords
```

Ou seja, a responsabilidade de cada importador é transformar o arquivo original em um DTO limpo e confiável.

Depois disso, o `DocumentImportService` salva `countries` e `institutions` como JSON na tabela `document`.

Posteriormente, a sincronização geográfica/institucional lê esses campos já salvos em `document.countries` e `document.institutions`. Portanto, se o importador já gravou lixo nesses campos, o sincronismo apenas tentará resolver esse lixo.

A correção precisa acontecer antes de salvar no banco.

---

## 3. Onde corrigir

Os ajustes devem ficar em três camadas:

1. **Importador da fonte**
   - `ScopusCsvImporter`
   - `WebOfScienceTxtImporter`, `WebOfScienceCsvImporter` ou equivalente, caso exista/venha a existir
   - importadores RIS, BibTeX, XLSX ou JSON, se também extraírem afiliações

2. **Normalizador comum de afiliações**
   - Serviço reutilizável para limpar país, instituição, endereço e unidade

3. **Validação de pré-importação**
   - Tela de preview deve mostrar alertas antes de salvar os documentos

A recomendação principal é não deixar cada importador inventar sua própria regra de extração. O ideal é criar um serviço único, por exemplo:

```text
src/Service/Import/AffiliationParserService.php
```

Esse serviço seria chamado por todos os importadores.

---

## 4. Problema específico no importador CSV do Scopus

No caso do Scopus CSV, o campo `Affiliations` está sendo lido corretamente, mas a extração interna é simplificada.

O fluxo atual é aproximadamente:

```php
$affRaw = $this->get($rawRecord, 'Affiliations');

if ($affRaw) {
    $dto->affiliations = array_filter(array_map('trim', explode(';', $affRaw)));
    $dto->countries = $this->extractCountries($affRaw);
    $dto->institutions = $this->extractInstitutions($affRaw);
}
```

O problema está nas funções `extractCountries()` e `extractInstitutions()`.

### 4.1. Países

O importador quebra as afiliações por `;`, depois por vírgula, e usa o último pedaço como país.

Isso falha quando o último pedaço é:

```text
FL 32611 USA
CA 95616 USA
TX 77843 USA
Peoples R China
```

O correto é normalizar esses valores antes de salvar.

Exemplo de regra:

```php
private function normalizeCountryFromAffiliationLastSegment(string $value): ?string
{
    $value = trim($value);

    // Ex.: FL 32611 USA, CA 95616 USA, TX 77843 USA
    if (preg_match('/^[A-Z]{2}\s+\d{5}(?:-\d{4})?\s+(USA|US|U\.S\.A\.)$/i', $value)) {
        return 'USA';
    }

    // Variação comum do Scopus
    if (preg_match('/^Peoples R China$/i', $value)) {
        return 'China';
    }

    // Variações de Reino Unido, se aparecerem
    if (preg_match('/^(England|Scotland|Wales|Northern Ireland)$/i', $value)) {
        return 'United Kingdom';
    }

    return $value !== '' ? $value : null;
}
```

### 4.2. Instituições

O importador atual aceita qualquer parte da afiliação que contenha termos como:

```text
universi
colleg
institut
school
hospital
center
centre
clinic
laboratory
lab
foundation
```

Essa abordagem ajuda, mas precisa de filtros negativos.

Antes de aceitar um trecho como instituição, o importador deve rejeitar valores que pareçam endereço.

Exemplo:

```php
private function isAddressLikeToken(string $value): bool
{
    $value = trim($value);

    if ($value === '') {
        return true;
    }

    // Ex.: 30 Xueyuan Rd, 1180 Ctr Dr, 5510 Nathan Shock Dr
    if (preg_match('/^\d+\s+/', $value)) {
        return true;
    }

    // CEP/endereço dos EUA
    if (preg_match('/^[A-Z]{2}\s+\d{5}(?:-\d{4})?\s+(USA|US|U\.S\.A\.)$/i', $value)) {
        return true;
    }

    // Termos comuns de endereço
    if (preg_match('/\b(rd|road|st|street|ave|avenue|blvd|boulevard|dr|drive|ctr|center|centre|ln|lane|way|postal|zip|pobox|po box)\b/i', $value)) {
        return true;
    }

    // Apenas cidade/estado/país isolado normalmente não é instituição
    if (preg_match('/^[A-Z]{2}$/', $value)) {
        return true;
    }

    return false;
}
```

E dentro de `extractInstitutions()`:

```php
foreach ($parts as $part) {
    $part = trim($part);

    if ($this->isAddressLikeToken($part)) {
        continue;
    }

    $lower = strtolower($part);

    if ($this->looksLikeInstitution($lower)) {
        $institutions[] = preg_replace('/\s+/', ' ', $part);
        break;
    }
}
```

## 5. Ajuste recomendado: criar um parser comum de afiliações

O melhor caminho é tirar as regras de dentro do `ScopusCsvImporter` e criar um parser reutilizável.

### 5.1. Serviço sugerido

Criar:

```text
src/Service/Import/AffiliationParserService.php
```

Com métodos como:

```php
final class AffiliationParserService
{
    public function splitAffiliations(?string $raw): array
    {
        if (!$raw) {
            return [];
        }

        return array_values(array_filter(array_map('trim', explode(';', $raw))));
    }

    public function extractCountries(string $rawAffiliations): array
    {
        $countries = [];

        foreach ($this->splitAffiliations($rawAffiliations) as $affiliation) {
            $country = $this->extractCountryFromSingleAffiliation($affiliation);

            if ($country !== null) {
                $countries[] = $country;
            }
        }

        return array_values(array_unique($countries));
    }

    public function extractInstitutions(string $rawAffiliations): array
    {
        $institutions = [];

        foreach ($this->splitAffiliations($rawAffiliations) as $affiliation) {
            $institution = $this->extractInstitutionFromSingleAffiliation($affiliation);

            if ($institution !== null) {
                $institutions[] = $institution;
            }
        }

        return array_values(array_unique($institutions));
    }
}
```

### 5.2. Vantagem

Com isso:

- Scopus CSV usa o mesmo parser;
- Web of Science TXT usa o mesmo parser;
- Web of Science CSV usa o mesmo parser;
- RIS/BibTeX também podem usar o mesmo parser se tiverem campo de afiliação;
- a correção de endereços e países fica em um único lugar.

## 6. Ajustes necessários para Web of Science TXT

O Web of Science em TXT normalmente usa campos de duas letras. Os campos mais importantes para afiliação/geografia costumam ser:

```text
C1  Author Address / Endereços dos autores
RP  Reprint Address
OI  ORCID
AF  Author Full Name
AU  Authors
TI  Title
SO  Source
PY  Publication Year
DI  DOI
DE  Author Keywords
ID  Keywords Plus
AB  Abstract
```

O campo mais importante para instituições e países é normalmente:

```text
C1
```

Exemplo conceitual:

```text
C1 [Smith, John] University of Florida, Gainesville, FL 32611 USA.
   [Zhang, Wei] Chinese Academy of Sciences, Beijing, Peoples R China.
```

### 6.1. O que o importador WoS TXT deve fazer

O importador TXT do Web of Science deve:

1. Ler registros separados por `ER`.
2. Agrupar linhas continuadas do mesmo campo.
3. Extrair o campo `C1`.
4. Separar cada endereço/autoria dentro de `C1`.
5. Remover o prefixo de autor entre colchetes.
6. Enviar o texto limpo para o parser comum de afiliações.

Exemplo:

```php
private function cleanWosAddressLine(string $line): string
{
    // Remove prefixo do autor: [Smith, John]
    $line = preg_replace('/^\[[^\]]+\]\s*/', '', trim($line));

    // Remove ponto final residual
    $line = rtrim($line, ". \t\n\r\0\x0B");

    return $line;
}
```

Depois:

```php
$cleanAddresses = [];

foreach ($c1Lines as $line) {
    $clean = $this->cleanWosAddressLine($line);

    if ($clean !== '') {
        $cleanAddresses[] = $clean;
    }
}

$affiliationText = implode('; ', $cleanAddresses);

$dto->affiliations = $this->affiliationParser->splitAffiliations($affiliationText);
$dto->countries = $this->affiliationParser->extractCountries($affiliationText);
$dto->institutions = $this->affiliationParser->extractInstitutions($affiliationText);
```

### 6.2. Cuidados no WoS TXT

O WoS TXT pode quebrar uma afiliação em múltiplas linhas. O importador não pode tratar cada linha como uma nova coluna. Ele precisa respeitar o formato de tags.

Exemplo:

```text
C1 [Autor A] Universidade X, Departamento Y, Cidade, Brazil.
   [Autor B] University Z, Center W, FL 32611 USA.
```

A segunda linha começa com espaços; isso normalmente significa continuação do campo anterior. Portanto, ela deve continuar pertencendo ao campo `C1`.

## 7. Ajustes necessários para Web of Science CSV

Se o Web of Science for importado em CSV, o cuidado é diferente.

O importador precisa ler por nome de coluna, não por posição.

Campos possíveis:

```text
Article Title
Authors
Author Full Names
Source Title
Publication Year
DOI
Abstract
Author Keywords
Keywords Plus
Addresses
Affiliations
Research Addresses
```

Como os nomes podem variar, o importador deve ter aliases.

Exemplo:

```php
private function getAny(array $record, array $keys): ?string
{
    foreach ($keys as $expected) {
        foreach ($record as $key => $value) {
            if (strcasecmp(trim($key), trim($expected)) === 0) {
                $value = trim((string) $value);
                return $value !== '' ? $value : null;
            }
        }
    }

    return null;
}
```

Uso:

```php
$affRaw = $this->getAny($rawRecord, [
    'Addresses',
    'Affiliations',
    'Research Addresses',
    'Author Address',
    'C1',
]);
```

Depois o valor deve ir para o parser comum:

```php
if ($affRaw) {
    $dto->affiliations = $this->affiliationParser->splitAffiliations($affRaw);
    $dto->countries = $this->affiliationParser->extractCountries($affRaw);
    $dto->institutions = $this->affiliationParser->extractInstitutions($affRaw);
}
```

## 8. Validação para detectar coluna deslocada

Além de corrigir o parse das afiliações, é importante detectar quando o CSV realmente foi lido com coluna errada.

### 8.1. Sinais de coluna deslocada

A importação deve emitir alerta se:

- a linha tem quantidade de colunas diferente do cabeçalho;
- `DOI` contém texto muito longo ou título;
- `Year` não é número;
- `Title` está vazio, mas `DOI` ou `Abstract` contém título;
- `Affiliations` está vazio em muitos registros, mas há texto de endereço em outra coluna;
- aparecem muitas instituições com números no começo;
- aparecem muitos países com CEP, rua ou estado.

### 8.2. Validador recomendado

Criar um serviço:

```text
src/Service/Import/ImportQualityAnalyzer.php
```

Ele pode analisar os 10 primeiros registros no preview e retornar alertas como:

```text
Possível problema de separador CSV.
Possível problema de aspas em campo com vírgulas.
Possíveis endereços detectados como instituições.
Possíveis CEPs detectados como países.
Campo Affiliations ausente ou vazio.
```

Exemplo de regra:

```php
private function looksSuspiciousInstitution(string $value): bool
{
    return preg_match('/^\d+\s+/', $value)
        || preg_match('/\b(rd|road|street|st|avenue|ave|blvd|drive|dr)\b/i', $value)
        || preg_match('/^[A-Z]{2}\s+\d{5}/', $value);
}
```

## 9. Ajustes na tela de preview

A tela de preview precisa mostrar não apenas o registro bruto, mas também o resultado da extração.

Para cada amostra, mostrar:

```text
Título
DOI
Afiliações brutas
Instituições extraídas
Países extraídos
Alertas
```

Exemplo de alerta:

```text
Atenção: estes valores parecem endereços, mas foram extraídos como instituição:
- 30 Xueyuan Rd
- 1180 Ctr Dr
```

Exemplo de alerta de país:

```text
Atenção: estes valores parecem estado + CEP + país, não país:
- FL 32611 USA
- CA 95616 USA
```

Assim, o problema é visto antes de confirmar a importação.

## 10. Regras mínimas que todos os importadores devem respeitar

Todo importador deve entregar o DTO já limpo.

### 10.1. `countries`

Deve conter somente países ou variações fortes de país:

```text
USA
China
Brazil
Germany
United Kingdom
Iran
```

Não deve conter:

```text
FL 32611 USA
CA 95616 USA
30 Xueyuan Rd
Gainesville
Beijing
```

### 10.2. `institutions`

Deve conter somente nomes institucionais:

```text
University of Florida
Chinese Academy of Sciences
Universidade de São Paulo
Embrapa Agricultura Digital
SINTEF Energy Research
```

Não deve conter:

```text
1180 Ctr Dr
30 Xueyuan Rd
FL 32611 USA
Beijing
Gainesville
```

### 10.3. `affiliations`

Pode conter o texto original limpo da afiliação, mas separado por autor/endereço quando possível.

Exemplo:

```json
[
  "University of Florida, Gainesville, FL 32611 USA",
  "Chinese Academy of Sciences, Beijing, China"
]
```

## 12. Comando de limpeza para dados já importados

Corrigir o importador não corrige documentos já salvos. Para isso, existem duas opções:

1. Reimportar os datasets após corrigir o importador.
2. Criar um comando de limpeza para `document.institutions` e `document.countries`.

Comando sugerido:

```text
php bin/console app:documents:clean-affiliations 5
```

Esse comando deve:

1. Carregar documentos do projeto.
2. Ler `document.institutions`.
3. Remover valores parecidos com endereço.
4. Ler `document.countries`.
5. Normalizar `FL 32611 USA` para `USA`.
6. Atualizar os JSONs.
7. Rodar novamente o enriquecimento geográfico/institucional.

Exemplo de lógica:

```php
$docs = $conn->fetchAllAssociative(
    'SELECT id, countries, institutions FROM document WHERE project_id = ?',
    [$projectId]
);

foreach ($docs as $doc) {
    $countries = json_decode($doc['countries'] ?? '[]', true) ?: [];
    $institutions = json_decode($doc['institutions'] ?? '[]', true) ?: [];

    $cleanCountries = [];
    foreach ($countries as $country) {
        $cleanCountries[] = $this->normalizeCountryFromAffiliationLastSegment($country);
    }

    $cleanInstitutions = [];
    foreach ($institutions as $institution) {
        if (!$this->isAddressLikeToken($institution)) {
            $cleanInstitutions[] = $institution;
        }
    }

    $conn->update('document', [
        'countries' => json_encode(array_values(array_unique(array_filter($cleanCountries))), JSON_UNESCAPED_UNICODE),
        'institutions' => json_encode(array_values(array_unique(array_filter($cleanInstitutions))), JSON_UNESCAPED_UNICODE),
    ], [
        'id' => $doc['id'],
    ]);
}
```

Depois:

```text
php bin/console app:project:sync-geography 5
```

Ou executar novamente pela interface:

```text
/projects/5/sync-geography
```

## 14. Resumo executivo

O ajuste necessário não é apenas cadastrar mais instituições.

O problema está antes: o importador está salvando partes da afiliação como se fossem instituições ou países.

A correção correta é:

```text
Arquivo original
↓
Importador específico da base
↓
Parser comum de afiliações
↓
DTO limpo
↓
DocumentImportService
↓
Sincronização geográfica/institucional
```

O sistema só deve cadastrar ou sincronizar dados que já passaram por uma limpeza mínima.

Se o valor for endereço, rua, CEP, cidade ou estado, ele não deve entrar em `document.institutions`.

Se o valor for `FL 32611 USA`, ele não deve entrar como país bruto final. Deve virar:

```text
country = USA
state = FL
postal_code = 32611
```

E, para dashboards bibliométricos, o agrupamento deve considerar:

```text
País: Estados Unidos
Estado: Florida
Instituição: University of Florida
```
